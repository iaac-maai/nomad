# NOMAD audit — 28 Oct 2026 (what is missing, wrong or leaking)

## Fixed today
| # | Problem | Fix |
|---|---|---|
| 1 | **Stale plan reading.** If the plan reader crashed or hung, NOMAD read the *previous* answer for that file and carried on. | Old answer deleted before each run; exit code and a 3-minute timeout checked; a clear error is shown instead (`src/rhino/nomad_core.py`). |
| 2 | **Memory leak in Rhino.** Pictures, brushes and fonts made for each sheet were never released, so a long Rhino session kept growing. | All drawing objects disposed after use (`nomad_sheet.py`, `nomad_model.py`). |
| 3 | **Pictures outside the Rhino file.** Sheets in NOMAD.3dm pointed to PNGs on disk; deleting the folder left blank plans. | Pictures are now embedded in the 3dm. |
| 4 | **Experiments redrawn differently.** Saved experiments were re-generated when drawn into NOMAD.3dm, so after a code change the file no longer matched the lab-book picture. | Recipes now store the finished result; the file shows exactly what was made. |
| 5 | **Silent scale guess.** Without a known façade length the plan scale is a guess (often ~50% off) and nothing said so. | A WARNING is written into the shop source on every sheet and panel. |
| 6 | **Flats outside the shop.** The generator could place a flat across the outline on a read plan. | New "Flats inside the shop" check marks it as failing (Stage 5). |
| 7 | **Rhino ignored start-up scripts** (since the D5 LiveSync plug-in). Background builds silently did nothing. | `src/rhino/run_in_rhino.ps1` types the command into a fresh Rhino and closes it. |
| 8 | **Text overlap / unreadable sheets.** | Sheets redrawn: white, no boxes, Arial, shorter rule lines. |

Checked and clean: no passwords, tokens or API keys in our files (`src`, `docs`, `book`, `results`, `rhino`, `grasshopper`).

## Flagged: known weaknesses (say them out loud in the presentation)
| # | Weakness | Why it matters | What would fix it |
|---|---|---|---|
| A | **Room sizes come from flats that already pass the rules** (Swiss Dwellings), and the same rules then check the generated flats. | Passing the room-size rules is partly built in; the real tests are fit, façade and density. Not a data leak into the *rule test* on real flats, but the generator's pass rate is optimistic. | Learn sizes from one set, test on another (ResPlan), or from Catalan housing data. |
| B | **Plan reader tested on our own drawings** of the Swiss shops (clean + messy). | Real scans (hand drawings, hatching, stamps) will be harder; 0.93 overlap is a best case. | Test on real CubiCasa5K scans or plans from the team. |
| C | **Daylight "lit" depth 5,5 m is a design assumption**, not an article. Bars owns daylight. | Stage 6 patios and the dark/usable split depend on it. | Replace with Bars's daylight analysis. |
| D | **Patio assumptions:** cut through the ground-floor roof; a room on a patio counts as lit; a patio counts as façade for Decret 141 3.6.2 and MPGM DA1 2.b. | Legally unconfirmed. | Ask the Ajuntament / a tutor; or read the rulebook text for "façana a espai públic" conditions. |
| E | **Height:** the dataset's `height_m` is used as clear height. | If Swiss height is floor-to-floor, clear height is lower (~0,3 m). | Confirm the Swiss Dwellings definition. |
| F | **Density (MPGM art. 318):** built area estimated as useful area / 0,9. | Real built area includes walls; cap may be off by one flat. | Use the cadastre built area (hypercadaster_ES). |
| G | **Access:** every street flat is assumed to have its own street door. | Some shopfronts may not allow it (ground-floor rules, fire). | Add an entrance rule card from CTE DB-SI / OME. |
| H | **New windows in blind walls** (slide "Pasul 5" intervention 1) are not tried: we do not know which outline edges face the street. | It is the biggest missing lever: most shops run out of façade, not depth. | Cadastre wall data (hypercadaster_ES, already cloned). |
| I | **Stages not built yet:** 2 meaning-based search, 3 full rule cards (only 9 rules coded), 9 evaluation golden set. | The presentation should show them as next steps. | — |
